# Claude Code ↔ Telegram Bridge

![Python](https://img.shields.io/badge/Python-3.12-3776AB?logo=python&logoColor=white)
![Platform](https://img.shields.io/badge/Platform-Windows-0078D6?logo=windows&logoColor=white)
![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)

Удалённое управление Claude Code на домашнем Windows ПК с Android через Telegram.
Бот принимает текстовые команды, запускает `claude -p` (headless) и возвращает ответ.

Что нового — в [WHATS_NEW.md](WHATS_NEW.md).

## Поток

```
Телефон → Telegram → python-telegram-bot (на ПК)
   → раннер (config.yaml: runner):
        subprocess → claude_runner: `claude -p` на каждое сообщение
        sdk        → sdk_runner: живая сессия Claude (Claude Agent SDK)
   → разбор JSON {result, session_id, total_cost_usd, num_turns}
   → ответ в Telegram (чанками / файлом + footer)
```

## Требования

- Windows, Python 3.10+ (проверено на 3.12).
- Claude Code CLI (`claude.exe`) с настроенной авторизацией.
- Токен Telegram-бота и ваш `chat_id` (в `.env`).

## Установка

```bat
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

## Настройка

1. Создайте бота: [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен.
2. Узнайте свой `chat_id`: напишите боту любое сообщение, затем откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — `chat.id` в ответе.
   (Удобнее — [@userinfobot](https://t.me/userinfobot).)
3. Заполните `.env` (скопировав из `.env.example`):

   ```ini
   TELEGRAM_BOT_TOKEN=123456:ABC-...
   ALLOWED_USER_IDS=<your_chat_id>
   ```

4. Отредактируйте `config.yaml`: укажите свои проекты (путь + имя).
   Режим по умолчанию, бюджет и deny-list — там же.

## Запуск

- **Запустить:** двойной клик по `run_bot.bat` (или `python -u bot.py`). Логи: `logs\bot.log`.
- **Остановить:**
  - проще всего — двойной клик по `stop_bot.bat` (убьёт все процессы `bot.py`,
    как бы он ни был запущен: `run_bot.bat`, автозапуск или фоновый шелл);
  - в окне терминала — `Ctrl+C` или закрыть окно;
  - если запущен автозапуском — `schtasks /End /TN "ClaudeTelegramBot"`.
- **Перезапустить** (нужно, чтобы подхватить правки кода): `stop_bot.bat`, затем
  снова `run_bot.bat`. Через автозапуск: `schtasks /End /TN "ClaudeTelegramBot"`,
  затем `schtasks /Run /TN "ClaudeTelegramBot"`.

Удалённо из Telegram бот **остановить или перезапустить нельзя** — такой команды
нет. Удалённо доступно только `/pause` /`/resume` (пауза обработки Claude, **не**
остановка процесса).

## Команды

| Команда | Действие |
|---|---|
| `/ask <текст>` | вопрос/анализ — **только чтение**, безопасно |
| `/task <текст>` | поручить работу (правка файлов по текущему режиму) |
| *(свободный текст)* | то же, что `/task` |
| `/new` | начать новый диалог Claude |
| `/diff` | `git diff` текущего проекта |
| `/git status\|log\|diff\|commit <msg>` | операции git |
| `/project` | список проектов; `/project <имя>` — переключить; `/project add <путь>` |
| `/mode` | текущий режим; `/mode balanced\|full\|strict\|manual` — сменить |
| `/cancel` | прервать текущий запрос (в sdk — с сохранением сессии) |
| `/pause` `/resume` | приостановить/возобновить обработку запросов к Claude (см. ниже) |
| `/status` | состояние: проект, режим, раннер, пауза, сессия, очередь, цена, статус серверов |
| `/note` | режим диктовки: голос и текст пишутся в файл без Claude (см. ниже) |

## Режимы (`/mode`)

- **balanced** *(по умолчанию)* — `acceptEdits`: правка кода разрешена, но заблокированы
  `rm -rf` и force-push; лимит бюджета на вызов.
- **full** — `--dangerously-skip-permissions`: любые команды без проверок (с подтверждением).
- **strict** — `plan`: только чтение/анализ, ничего не меняет.
- **manual** — *только с `runner: sdk`*: каждое действие Claude (файл, команда…)
  приходит сообщением с кнопками **✅ Разрешить / ❌ Отклонить** — вы решаете сами.

`/ask` **всегда** только для чтения, независимо от режима.

## Раннер: `subprocess` | `sdk`

В `config.yaml` задаётся исполнитель Claude (`runner`, по умолчанию `subprocess`;
меняется также через `/config`, применяется после перезапуска бота):

- **`subprocess`** *(по умолчанию)* — привычное поведение: на каждое сообщение
  запускается `claude -p`, ответ парсится из JSON. Зависимостей сверх CLI не требует.
- **`sdk`** — **живая сессия** Claude через Claude Agent SDK (pip-пакет
  `claude-agent-sdk` уже в `requirements.txt`, ~200 МБ: CLI идёт в комплекте).
  Контекст живёт в сессии и не пересобирается заново на каждое сообщение, а:

  - **Кнопки прав ✅/❌.** Опасные действия (запись файла, команды) приходят
    сообщением с кнопками; не ответили за `permission_timeout_minutes` (10 мин
    по умолчанию) — вызов автоматически отклоняется. Уточняющие вопросы Claude
    тоже приходят кнопками с вариантами ответа.
  - **Настоящий `/cancel`** — прерывает ход, не убивая сессию: следующий вопрос
    продолжит тот же диалог.
  - **Очередь сообщений.** Пока идёт ход (или ждёт вашу кнопку), новые сообщения
    не отклоняются, а копятся в очередь (`task_queue_max`, 3 по умолчанию) и
    уходят по одному. `/cancel` чистит очередь, `/resume` возобновляет раздачу.
  - `/new` и смена проекта закрывают живую сессию; контекст прошлых сессий
    сохранён и подхватывается при возврате. **Пока идёт запрос — оба запрещены**
    (иначе прервали бы его): бот ответит «⏳ дождитесь или /cancel» — повторите
    после окончания.

  `stop_bot.bat` прибирает и осиротевший CLI sdk-раннера (только его — ваш
  интерактивный `claude` не трогает).

## Пауза (`/pause` /`/resume`)

`/pause` временно приостанавливает обработку запросов к Claude для вашего чата:
- Идущий запрос (если Claude уже считает) дорабатывает до конца.
- Новые `/ask` и `/task` отвечают «⏸ на паузе»; свободный текст и голосовые
  **молча игнорируются** (без ответа) — отвечать будут только команды.
- Остальные команды (`/status`, `/git`, `/diff`, `/project`, …) продолжают работать.
- `/resume` снимает паузу.

Состояние хранится в памяти: после ручного перезапуска бота всегда «возобновлено».
Исключение — **автозапуск** (см. ниже): бот поднимается на паузе, `/resume` включает.

## Голосовые сообщения 🎙

Можно надиктовать команду голосом — бот расшифрует и выполнит её как задачу.
Telegram сам голос не распознаёт для бота, поэтому расшифровка идёт через STT
(настраивается в `config.yaml`, секция `stt`):

- **`provider: groq`** *(по умолчанию)* — облако, быстро, отлично распознаёт русский.
  Нужен бесплатный ключ: <https://console.groq.com/keys> → положите в `.env`:
  ```
  GROQ_API_KEY=gsk_...
  ```
- **`provider: local`** — офлайн на этом ПК, бесплатно навсегда, приватно.
  Один раз установите (модель скачается при первом голосовом):
  ```
  .venv\Scripts\pip install faster-whisper
  ```
  Размер/качество модели задаёт `stt.local_model` (`tiny`…`large-v3`).

Язык — `stt.language` (`ru` по умолчанию; пусто = автоопределение).

## Голосовые ответы (/speak) 🔊

Ответы по умолчанию приходят текстом. Команда **`/speak`** озвучивает голосом
последний ответ Claude (text-to-speech) и присылает голосовое сообщение.

- Движок: `config.yaml`, секция `tts`.
  - `provider: edge` *(по умолчанию)* — Microsoft Edge TTS, бесплатно, отличные
    русские голоса (`edge_voice`, напр. `ru-RU-SvetlanaNeural`, `ru-RU-DmitriNeural`).
  - `provider: silero` — офлайн (нужен `pip install torch`, модель скачается при первом запуске).
- Нужен **ffmpeg** (для кодирования в OGG/Opus): `winget install Gyan.FFmpeg`.
  Путь подхватывается автоматически; можно задать явно в `tts.ffmpeg_path`.

## Диктовка (`/note`) 📝

Режим «диктовки» — отдельный от обычного голосового ввода: надиктованное
**распознаётся и дописывается в файл-журнал**, **без обращения к Claude**
(не тратит квоту, не занимает очередь). Удобно для голосовых заметок и
дневника с телефона.

- `/note on` / `/note off` — включить/выключить. Пока включено, **все**
  голосовые сообщения **и набранные тексты** пишутся в файл (Claude не
  вызывается; вопрос Claude — через `/ask` или `/task`).
- `/note folder <имя>` — сменить папку-категорию (напр. `work`, `идеи`).
  По умолчанию `default`; папка создаётся при первой записи.
- `/note` — статус: режим, текущая папка, сегодняшний файл.
- `/note browse` — листать прошлые записи **inline-кнопками**:
  папки → файлы (по дням) → **меню файла**: `👁 Просмотреть` (текст в чат) /
  `📄 Скачать .md` (файл целиком, открыть в Obsidian или переслать) / `← назад`.
  Имя файла показывается без `.md` — иначе Telegram превращает `2026-06-21.md`
  в кликабельную (битую) ссылку.

Записи лежат в `dictations\<папка>\ГГГГ-ММ-ДД.md` (один файл на день,
дописывается). Каталог `dictations\` добавлен в `.gitignore`. Параметры —
`config.yaml`, секция `dictations` (`dir`, `default_folder`).

Диктовка **работает и на паузе** Claude (`/pause`) — она его не касается.
Голос и свободный текст пишутся в журнал; команды (`/ask`, `/task`,
`/note off`, …) работают как обычно.

## Старт бота и статус серверов 🌐

При каждом запуске бот первым сообщением присылает владельцу **статус +
список команд + проверку связи с серверами** — чтобы сразу видеть, что бот
поднялся и всё ли доступно. Накопленные пока бот лежал сообщения при старте
**сбрасываются** (не выполняются заново) — поэтому не бывает «шторма»
индикатора набора и каскада ошибок (например, когда API Claude недоступен).

Команда **`/status`** помимо проекта/режима/паузы/сессии показывает то же —
**статус соединения с серверами** (`health.py`):

- ✅/❌ **Telegram** — связь с API Telegram.
- ✅/❌ **Claude API** — достижимость endpoint из `ANTHROPIC_BASE_URL`
  (именно его недоступность даёт `ConnectionRefused` от `claude -p`).
- ✅/❌ **Groq STT** / **Edge TTS** — если используются; локальные провайдеры
  (faster-whisper, silero) показываются как «локально».

Проверки идут параллельно (таймаут 5 с): любой HTTP-ответ = сервер жив,
сетевая ошибка = ❌. Токен бота и ключи в вывод не попадают.

## Безопасность

- Бот отвечает только пользователям из `ALLOWED_USER_IDS`; чужие игнорируются.
- Токен в `.env` (в `.gitignore`), никогда не логируется.
- Все вызовы `claude` сериализованы одним локом — конкурентные процессы
  калечат глобальный `~/.claude.json`, поэтому параллельных запусков нет.

## Архитектура (файлы)

- `bot.py` — точка входа: логирование, регистрация хендлеров, `run_polling`.
- `config.py` — загрузка `.env` + `config.yaml`, дата-классы `Settings`/`Project`.
- `claude_runner.py` — обёртка над `claude -p` (argv, stdin, защитный разбор JSON, kill, таймаут).
- `sdk_runner.py` — живая сессия через Claude Agent SDK (опциональный пакет,
  lazy-import; кнопки прав ✅/❌, настоящий `/cancel`, режим manual).
- `projects.py` — состояние: текущий проект, сессии (`sessions.json`), глобальный лок, `/cancel`.
- `commands.py` — обработчики команд.
- `messages.py` — чанкование/файл/footer.
- `security.py` — фильтр по `ALLOWED_USER_IDS`.
- `mt5bot\` — второй бот: монитор терминала MetaTrader 5 (наблюдение + действия
  над существующими объектами + скриншоты): `mt5_bot.py` (точка входа, guard
  токенов), `mt5_monitor.py` (attach/poll/события), `GRE_Shot.mq5` (индикатор
  для снимков графиков — вешается в терминал), свои run/stop/автозапуск и
  `logs\mt5bot.log`.

## Автозапуск при старте Windows

Бот может запускаться автоматически при входе в систему и стартовать **на паузе**
(безопасно: Claude ничего не выполнит, пока вы не пришлёте `/resume`).

- **`install_autostart.bat`** — создаёт задачу планировщика `ClaudeTelegramBot`
  (триггер «при входе», от вашего пользователя, **без прав админа**).
  Запускает `run_autostart.vbs` → `pythonw.exe` (без окна консоли) с env
  `BOT_START_PAUSED=1`, поэтому бот поднимается на паузе.
- **`uninstall_autostart.bat`** — удаляет задачу (текущий процесс бота не останавливает).

Нюансы:
- Это «при входе», а не «при загрузке системы»: Claude CLI читает `~/.claude.json`
  из профиля пользователя, поэтому бот обязан работать от вашего пользователя
  (запуск от `SYSTEM` сломал бы конфиг Claude).
- Без авто-рестарта при падении — сетевые сбои бот пережидает сам, жёсткие краши редки.
- Ручной `run_bot.bat` стартует **активным** (без паузы) — удобно для отладки.
- Проверить без перелогина: остановите текущий бот, затем
  `schtasks /Run /TN "ClaudeTelegramBot"`.

## Второй бот: MT5-монитор (`mt5bot\`) 📈

В этом же репо живёт второй, полностью независимый бот — наблюдатель за
торговым терминалом MetaTrader 5 (bossaFX). Свой токен, свой процесс, свой
лог; Claude-часть моста не импортируется вообще. Фаза 1 — наблюдение **плюс
действия над существующими объектами**: закрыть позицию / удалить pending
(за флагом `mt5.allow_trading` и с подтверждением ✅), **плюс скриншоты
графиков** (фаза 3) и **включение/выключение терминала**. Выставление новых
ордеров — будущая фаза.

Что делает:
- подключается к **запущенному** терминалу (терминал должен работать на той же
  машине) и каждые 2 секунды сверяет ордера / позиции / историю сделок.
  Закрытый терминал бот **сам не запускает** — проверяет процесс и ждёт
  (уведомит «недоступен»), чтобы ненароком не воскресить выключенный терминал
  с работающим советником. Запуск по команде владельца — единственное
  исключение: `/mt5on` (см. «Питание терминала»);
- шлёт уведомления: 📈 выставлен pending, ✅ fill, 🎯/🛑 закрытие с причиной
  (TP/SL/EXPERT) и профитом, ⚠️ низкий margin level (однократно, с гистерезисом);
  при сбое сети отправка повторяется (событие не теряется — доедет, когда
  связь вернётся);
- команды: `/mt5status` · `/mt5orders` · `/mt5positions` · `/mt5shot` ·
  `/mt5on` · `/mt5off` (и `/help`) — полные имена, чтобы тап по команде в чате
  отправлял её целиком (аргумент после пробела в тап не попадает — ограничение
  Telegram). Короткая форма `/mt5 <status|orders|positions|chart|term|off|on>`
  тоже работает при наборе руками;
- **списки — блоками с «цветом»**: каждая позиция/ордер отделены пустой строкой;
  у позиций 🟢/🔴 = **плюс/минус** (точка стоит рядом с суммой), направление —
  словом BUY/SELL; у pending 📈/📉 по направлению. Другого способа выделить
  цвет в Telegram-тексте нет;
- **действия по тапу**: у каждой позиции/ордера в списке своя кнопка — тап
  открывает карточку с действием (**закрыть по рынку** / **удалить pending**) и
  экраном подтверждения ✅/❌. Торговые действия работают только при
  `mt5.allow_trading: true` (по умолчанию `false` — бот честно откажет); если
  в терминале выключена автоторговля, ответ объяснит про кнопку AutoTrading;
- **📸 снимки графиков в чат**: `/mt5shot` (или кнопка «📸 График») открывает
  **меню выбора графика** — кнопка «Все графики» плюс по кнопке на каждый
  символ графика с GRE_Shot: при подключении бот сам опрашивает графики
  («кто жив?» — индикатор отвечает маленьким файлом, без снимка), то же делает
  кнопка «🔄 Обновить список» в меню; список пополняют и ордера/позиции
  терминала, и сами раунды снимков.
  Снимает графики, на которые повешен индикатор **GRE_Shot**, — с дашбордом
  советника (Room, фильтры), чего нет в текстовых командах. Несколько графиков —
  несколько фото (кроме графиков одного символа — им достанется один снимок);
  `/mt5shot BTCUSD` — сразу только указанный символ. Подробности и
  настройка — ниже, «Снимки графиков (GRE_Shot)»;
- **⏻ питание терминала**: `/mt5off` (подтверждение ✅ — советник
  приостановится, позиции останутся на сервере с TP/SL) и `/mt5on` (запуск;
  монитор подключится сам и пришлёт резюме). Работает при
  `mt5.allow_trading: true` и заданном `mt5.terminal_path`; кнопка ⏻ есть и в
  пульте `/mt5`, и в нижней постоянной клавиатуре;
- **кнопки вместо набора команд** — двух видов:
  - **постоянная клавиатура внизу чата** («📊 Статус · ⏳ Ордера · 📋 Позиции ·
    📸 График · ⏻ Терминал») —
    появляется сама, уже вместе со стартовым сообщением бота, и остаётся
    всегда: тап по кнопке — и ответ. Ничего набирать и вспоминать не нужно;
    если свернули её в Telegram — вернёт `/start`.
  - **пульт `/mt5`** — сообщение с inline-кнопками: тап обновляет **то же
    самое сообщение** свежими данными (чат не засоряется историей запросов).

Настройка и запуск:
1. Создайте **второго** бота у @BotFather и добавьте его токен в `.env`:
   `MT5_BOT_TOKEN=...` Использовать токен первого бота нельзя — бот откажется
   стартовать (защита от 409).
2. Секция `mt5:` в `config.yaml` — путь терминала, порог margin, интервал
   опроса. Пакет `MetaTrader5` уже в `requirements.txt`.
3. Запуск: `mt5bot\run_mt5bot.bat`, остановка: `mt5bot\stop_mt5bot.bat`
   (stop-скрипты двух ботов взаимно строгие и соседа не задевают).
4. Автозапуск: `mt5bot\install_mt5bot_autostart.bat` — задача `MT5TelegramBot`,
   стартует **активным** (его работа — уведомления, пауза не нужна).
5. Для снимков графиков — один раз повесьте индикатор **GRE_Shot** (см. ниже).

### Снимки графиков (GRE_Shot)

`ChartScreenShot()` в MQL5 умеет делать PNG своего графика, но вызвать его из
Python нельзя — поэтому в терминале живёт мини-индикатор GRE_Shot, а бот общается
с ним через файл в общем каталоге терминалов (nonce-протокол). Один раз:

1. Скопируйте `mt5bot\GRE_Shot.mq5` в `<терминал>\MQL5\Indicators\` и
   скомпилируйте в MetaEditor (F7) — либо положите готовый `GRE_Shot.ex5`.
2. В терминале обновите Навигатор и перетащите **GRE_Shot** на каждый график,
   который хотите видеть (обычно — графики с советником; автоторговля для
   индикатора не нужна, он ничего не торгует). Признак жизни — маленькая
   надпись **GRE_Shot · ЧЧ:ММ:СС** в правом верхнем углу графика, сразу
   под именем советника (его в этом углу рисует сам терминал): секунды
   тикают = опрос идёт; после снимка там же появляется «last: символ время».
   Сам индикатор прозрачен (ничего не рисует и не мешает советнику).
3. Готово: `/mt5shot` в чате → бот пришлёт PNG каждого графика с GRE_Shot
   (с дашбордом советника — Room, spread, фильтры). `/mt5shot <символ>` —
   снимок только одного символа; `/mt5 chart` — то же самое.

Снимки приходят новыми сообщениями (фото нельзя «вклеить» в текстовый экран
пульта). Файлы снимков бот подчищает сам — и собранные, и «опоздавшие»
(написанные после отбора), так что на диске ничего не копится. Если открыто
несколько графиков **одного символа** (например, разные таймфреймы) — придёт
один снимок этого символа. Пока идёт съёмка, повторный запрос получает
«⏳ Снимок уже делается».

### Питание терминала (`/mt5on` · `/mt5off`)

Терминал можно выключать и включать прямо из Telegram (кнопка ⏻ — в пульте
`/mt5` и в нижней клавиатуре, или команды). Требования: задан `mt5.terminal_path` и включён
`mt5.allow_trading` — это то же оружие, что и торговые действия, поэтому оно
за тем же ключом.

- **`/mt5off`** — экран подтверждения ✅/❌ (с предупреждением, если открыты
  позиции: пока терминал выключен, советник ими не управляет; TP/SL остаются
  на сервере и продолжают работать). Закрытие мягкое, как крестик: WM_CLOSE,
  терминал сохраняет состояние; если за 15 с не закрылся (висит диалог) —
  принудительное завершение с честным отчётом.
- **`/mt5on`** — запускает тот же exe с тем же профилем (советник возобновляет
  работу). Монитор сам подключится в течение ~5–30 с и пришлёт 📡-резюме
  (включая количество сделок за простой).

Автоматика по-прежнему никогда ничего не запускает сама: монитор подключается
только к уже работающему терминалу — запуск возможен исключительно явной
командой владельца.

Проверка без Telegram (токен не нужен):

```
PYTHONUTF8=1 SMOKE=attach .venv\Scripts\python.exe mt5bot\mt5_bot.py
```

— подключится к терминалу и напечатает статус/ордера/позиции в консоль.
