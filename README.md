# Claude Code ↔ Telegram Bridge

![Python](https://img.shields.io/badge/Python-3.12-3776AB?logo=python&logoColor=white)
![Platform](https://img.shields.io/badge/Platform-Windows-0078D6?logo=windows&logoColor=white)
![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)

Удалённое управление Claude Code на домашнем Windows ПК с Android через Telegram.
Бот принимает текстовые команды, запускает `claude -p` (headless) и возвращает ответ.

Что нового — в [WHATS_NEW.md](WHATS_NEW.md).

## Поток

```
Телефон → Telegram → python-telegram-bot (на ПК)
   → claude_runner: `claude -p` (cwd = папка проекта, промпт через stdin)
   → разбор JSON {result, session_id, total_cost_usd, num_turns}
   → ответ в Telegram (чанками / файлом + footer)
```

## Требования

- Windows, Python 3.10+ (проверено на 3.12).
- Claude Code CLI (`claude.exe`) с настроенной авторизацией.
- Токен Telegram-бота и ваш `chat_id` (в `.env`).

## Установка

```bat
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

## Настройка

1. Создайте бота: [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен.
2. Узнайте свой `chat_id`: напишите боту любое сообщение, затем откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — `chat.id` в ответе.
   (Удобнее — [@userinfobot](https://t.me/userinfobot).)
3. Заполните `.env` (скопировав из `.env.example`):

   ```ini
   TELEGRAM_BOT_TOKEN=123456:ABC-...
   ALLOWED_USER_IDS=<your_chat_id>
   ```

4. Отредактируйте `config.yaml`: укажите свои проекты (путь + имя).
   Режим по умолчанию, бюджет и deny-list — там же.

## Запуск

- **Запустить:** двойной клик по `run_bot.bat` (или `python -u bot.py`). Логи: `logs\bot.log`.
- **Остановить:**
  - проще всего — двойной клик по `stop_bot.bat` (убьёт все процессы `bot.py`,
    как бы он ни был запущен: `run_bot.bat`, автозапуск или фоновый шелл);
  - в окне терминала — `Ctrl+C` или закрыть окно;
  - если запущен автозапуском — `schtasks /End /TN "ClaudeTelegramBot"`.
- **Перезапустить** (нужно, чтобы подхватить правки кода): `stop_bot.bat`, затем
  снова `run_bot.bat`. Через автозапуск: `schtasks /End /TN "ClaudeTelegramBot"`,
  затем `schtasks /Run /TN "ClaudeTelegramBot"`.

Удалённо из Telegram бот **остановить или перезапустить нельзя** — такой команды
нет. Удалённо доступно только `/pause` /`/resume` (пауза обработки Claude, **не**
остановка процесса).

## Команды

| Команда | Действие |
|---|---|
| `/ask <текст>` | вопрос/анализ — **только чтение**, безопасно |
| `/task <текст>` | поручить работу (правка файлов по текущему режиму) |
| *(свободный текст)* | то же, что `/task` |
| `/new` | начать новый диалог Claude |
| `/diff` | `git diff` текущего проекта |
| `/git status\|log\|diff\|commit <msg>` | операции git |
| `/project` | список проектов; `/project <имя>` — переключить; `/project add <путь>` |
| `/mode` | текущий режим; `/mode balanced\|full\|strict` — сменить |
| `/cancel` | прервать текущий запрос |
| `/pause` `/resume` | приостановить/возобновить обработку запросов к Claude (см. ниже) |
| `/status` | состояние: проект, режим, пауза, сессия, цена, статус серверов |
| `/note` | режим диктовки: голос пишется в файл без Claude (см. ниже) |

## Режимы (`/mode`)

- **balanced** *(по умолчанию)* — `acceptEdits`: правка кода разрешена, но заблокированы
  `rm -rf` и force-push; лимит бюджета на вызов.
- **full** — `--dangerously-skip-permissions`: любые команды без проверок (с подтверждением).
- **strict** — `plan`: только чтение/анализ, ничего не меняет.

`/ask` **всегда** только для чтения, независимо от режима.

## Пауза (`/pause` /`/resume`)

`/pause` временно приостанавливает обработку запросов к Claude для вашего чата:
- Идущий запрос (если Claude уже считает) дорабатывает до конца.
- Новые `/ask` и `/task` отвечают «⏸ на паузе»; свободный текст и голосовые
  **молча игнорируются** (без ответа) — отвечать будут только команды.
- Остальные команды (`/status`, `/git`, `/diff`, `/project`, …) продолжают работать.
- `/resume` снимает паузу.

Состояние хранится в памяти: после ручного перезапуска бота всегда «возобновлено».
Исключение — **автозапуск** (см. ниже): бот поднимается на паузе, `/resume` включает.

## Голосовые сообщения 🎙

Можно надиктовать команду голосом — бот расшифрует и выполнит её как задачу.
Telegram сам голос не распознаёт для бота, поэтому расшифровка идёт через STT
(настраивается в `config.yaml`, секция `stt`):

- **`provider: groq`** *(по умолчанию)* — облако, быстро, отлично распознаёт русский.
  Нужен бесплатный ключ: <https://console.groq.com/keys> → положите в `.env`:
  ```
  GROQ_API_KEY=gsk_...
  ```
- **`provider: local`** — офлайн на этом ПК, бесплатно навсегда, приватно.
  Один раз установите (модель скачается при первом голосовом):
  ```
  .venv\Scripts\pip install faster-whisper
  ```
  Размер/качество модели задаёт `stt.local_model` (`tiny`…`large-v3`).

Язык — `stt.language` (`ru` по умолчанию; пусто = автоопределение).

## Голосовые ответы (/speak) 🔊

Ответы по умолчанию приходят текстом. Команда **`/speak`** озвучивает голосом
последний ответ Claude (text-to-speech) и присылает голосовое сообщение.

- Движок: `config.yaml`, секция `tts`.
  - `provider: edge` *(по умолчанию)* — Microsoft Edge TTS, бесплатно, отличные
    русские голоса (`edge_voice`, напр. `ru-RU-SvetlanaNeural`, `ru-RU-DmitriNeural`).
  - `provider: silero` — офлайн (нужен `pip install torch`, модель скачается при первом запуске).
- Нужен **ffmpeg** (для кодирования в OGG/Opus): `winget install Gyan.FFmpeg`.
  Путь подхватывается автоматически; можно задать явно в `tts.ffmpeg_path`.

## Диктовка (`/note`) 📝

Режим «диктовки» — отдельный от обычного голосового ввода: надиктованное
**распознаётся и дописывается в файл-журнал**, **без обращения к Claude**
(не тратит квоту, не занимает очередь). Удобно для голосовых заметок и
дневника с телефона.

- `/note on` / `/note off` — включить/выключить. Пока включено, **все**
  голосовые сообщения пишутся в файл (Claude не вызывается).
- `/note folder <имя>` — сменить папку-категорию (напр. `work`, `идеи`).
  По умолчанию `default`; папка создаётся при первой записи.
- `/note` — статус: режим, текущая папка, сегодняшний файл.
- `/note browse` — листать прошлые записи **inline-кнопками**:
  папки → файлы (по дням) → **меню файла**: `👁 Просмотреть` (текст в чат) /
  `📄 Скачать .md` (файл целиком, открыть в Obsidian или переслать) / `← назад`.
  Имя файла показывается без `.md` — иначе Telegram превращает `2026-06-21.md`
  в кликабельную (битую) ссылку.

Записи лежат в `dictations\<папка>\ГГГГ-ММ-ДД.md` (один файл на день,
дописывается). Каталог `dictations\` добавлен в `.gitignore`. Параметры —
`config.yaml`, секция `dictations` (`dir`, `default_folder`).

Диктовка **работает и на паузе** Claude (`/pause`) — она его не касается.
Текстовые сообщения по-прежнему идут в Claude; режим диктовки касается
только голосовых.

## Старт бота и статус серверов 🌐

При каждом запуске бот первым сообщением присылает владельцу **статус +
список команд + проверку связи с серверами** — чтобы сразу видеть, что бот
поднялся и всё ли доступно. Накопленные пока бот лежал сообщения при старте
**сбрасываются** (не выполняются заново) — поэтому не бывает «шторма»
индикатора набора и каскада ошибок (например, когда API Claude недоступен).

Команда **`/status`** помимо проекта/режима/паузы/сессии показывает то же —
**статус соединения с серверами** (`health.py`):

- ✅/❌ **Telegram** — связь с API Telegram.
- ✅/❌ **Claude API** — достижимость endpoint из `ANTHROPIC_BASE_URL`
  (именно его недоступность даёт `ConnectionRefused` от `claude -p`).
- ✅/❌ **Groq STT** / **Edge TTS** — если используются; локальные провайдеры
  (faster-whisper, silero) показываются как «локально».

Проверки идут параллельно (таймаут 5 с): любой HTTP-ответ = сервер жив,
сетевая ошибка = ❌. Токен бота и ключи в вывод не попадают.

## Безопасность

- Бот отвечает только пользователям из `ALLOWED_USER_IDS`; чужие игнорируются.
- Токен в `.env` (в `.gitignore`), никогда не логируется.
- Все вызовы `claude` сериализованы одним локом — конкурентные процессы
  калечат глобальный `~/.claude.json`, поэтому параллельных запусков нет.

## Архитектура (файлы)

- `bot.py` — точка входа: логирование, регистрация хендлеров, `run_polling`.
- `config.py` — загрузка `.env` + `config.yaml`, дата-классы `Settings`/`Project`.
- `claude_runner.py` — обёртка над `claude -p` (argv, stdin, защитный разбор JSON, kill, таймаут).
- `projects.py` — состояние: текущий проект, сессии (`sessions.json`), глобальный лок, `/cancel`.
- `commands.py` — обработчики команд.
- `messages.py` — чанкование/файл/footer.
- `security.py` — фильтр по `ALLOWED_USER_IDS`.

## Автозапуск при старте Windows

Бот может запускаться автоматически при входе в систему и стартовать **на паузе**
(безопасно: Claude ничего не выполнит, пока вы не пришлёте `/resume`).

- **`install_autostart.bat`** — создаёт задачу планировщика `ClaudeTelegramBot`
  (триггер «при входе», от вашего пользователя, **без прав админа**).
  Запускает `run_autostart.vbs` → `pythonw.exe` (без окна консоли) с env
  `BOT_START_PAUSED=1`, поэтому бот поднимается на паузе.
- **`uninstall_autostart.bat`** — удаляет задачу (текущий процесс бота не останавливает).

Нюансы:
- Это «при входе», а не «при загрузке системы»: Claude CLI читает `~/.claude.json`
  из профиля пользователя, поэтому бот обязан работать от вашего пользователя
  (запуск от `SYSTEM` сломал бы конфиг Claude).
- Без авто-рестарта при падении — сетевые сбои бот пережидает сам, жёсткие краши редки.
- Ручной `run_bot.bat` стартует **активным** (без паузы) — удобно для отладки.
- Проверить без перелогина: остановите текущий бот, затем
  `schtasks /Run /TN "ClaudeTelegramBot"`.
