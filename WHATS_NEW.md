## 2026-09-16

- **Второй бот: MT5-монитор (фаза 1 — наблюдение).** Новая папка `mt5bot\`:
  отдельный процесс со своим токеном (`MT5_BOT_TOKEN` в `.env` — создайте
  второго бота у @BotFather), Claude-часть не импортирует вообще. Подключается
  к запущенному терминалу bossaFX, следит за ордерами/позициями/историей и
  шлёт уведомления: 📈 выставлен pending, ✅ fill, 🎯/🛑 закрытие (причина
  TP/SL/EXPERT + профит), ⚠️ низкий margin level. Команды: `/mt5status` ·
  `/mt5orders` · `/mt5positions` (полные имена — тап в чате шлёт команду
  целиком; есть меню автодополнения). Управление — **кнопками**: постоянная
  клавиатура внизу чата (📊 Статус · ⏳ Ордера · 📋 Позиции — появляется сама со
  стартовым сообщением, тап — и ответ) и пульт `/mt5` с обновлением на месте.
  Списки позиций/ордеров — блоками с цветными метками (у позиций 🟢/🔴 =
  плюс/минус, у pending 📈/📉 по направлению), каждый элемент отделён пустой
  строкой — на телефоне не сливается. **Тап по позиции/ордеру в списке открывает действия**: закрыть по
  рынку / удалить pending — с экраном подтверждения ✅/❌ (работает при
  `mt5.allow_trading: true`, пока выключено — бот отказывает с объяснением).
  Выставление новых ордеров и скриншоты — фазы 2–3
  (торговля будет за флагом `mt5.allow_trading`, пока `false`).
- **`stop_bot.bat` фильтрует строго `bot.py`** (границы слова): имя
  `mt5_bot.py` содержит подстроку `bot.py`, и старый фильтр убил бы соседний
  бот терминала. Взаимный тест пройден: стоп Claude не трогает MT5 и наоборот.
- **Уведомления MT5 переживают сбой сети** (по ревью): события сделок/margin
  идут через очередь с повторами отправки (5 с → 60 с, ~час попыток) —
  раньше неудачная отправка теряла событие навсегда. Заодно закрыт обход
  защиты «не запускать закрытый терминал» при пустом `terminal_path`, а тап
  торгового действия при выключенном `allow_trading` теперь говорит об этом
  сразу в карточке (без лишних экранов подтверждения).
- **Фикс логирования чужих апдейтов** (общий `security.py`, касается обоих
  ботов): тап постороннего по inline-кнопке без текста сообщения больше не
  даёт TypeError в логе.
- **Смена проекта и `/new` запрещены, пока идёт запрос** (раннер `sdk`). Раньше
  они закрывали живую сессию Claude «под ногами» — идущий запрос обрывался, а
  `/new` ещё и отменялся сам (завершившийся запрос возвращал свой номер сессии).
  Теперь бот сразу отвечает: «⏳ идёт запрос — дождитесь или /cancel».
- **`/cancel` честно про окно старта.** Пока SDK-сессия поднимается (первые
  секунды запроса), прервать ход нельзя — раньше бот врал «Сейчас ничего не
  выполняется»; теперь говорит «запрос ещё поднимается, повторите через
  несколько секунд» (заодно чистит очередь).
- **Переключатель раннера в `/config` больше не меняет его на лету** — только
  записывает в `config.yaml`; применяется рестартом (менять исполнитель Claude
  под работающим ботом ломало очередь сообщений). `/status` показывает раннер,
  на котором процесс реально работает.
- **Кнопки ✅/❌ не зависают «зомби».** Если SDK-сессия падала, пока висел
  запрос прав, кнопки оставались активными навсегда — теперь все висящие
  запросы закрываются как отклонённые.
- **Фикс `stop_bot.bat`:** зачистка осиротевшего CLI раннера `sdk` убивала
  сама себя (эталон поиска совпадал с командной строкой самого скрипта) —
  добавлен фильтр по имени процесса.
- **Диктовка принимает и текст.** В режиме `/note` в файл-журнал пишутся не
  только голосовые, но и набранные с клавиатуры сообщения (голос и текст —
  одинаково, Claude не вызывается; вопросы ему — через `/ask`/`/task`).
  Работает и на паузе Claude.
- **`/help` перегруппирован по действиям:** диалог с Claude · голос · заметки ·
  проекты и git · режимы и управление.

## 2026-09-15

- **Фикс: «Claude не завершил запрос» с дампом HTTP-логов.** Если бот был
  запущен из оболочки с переменной `ANTHROPIC_LOG=debug`, CLI печатал
  отладочные логи в тот же поток, что и JSON-ответ — готовый ответ терялся, а
  вместо него приходил кусок дампа. Теперь бот вычищает эту переменную при
  старте (и у дочернего процесса), разбор вывода переживает посторонний мусор
  в stdout (JSON ищется с конца потока), а при неразборчивом выводе в лог
  пишется хвост — там причина, а не первые 4000 символов шума.

## 2026-09-10

- **Новый раннер: `sdk` (живая сессия Claude).** В `config.yaml` появился
  переключатель `runner: subprocess | sdk` (по умолчанию прежний `subprocess` —
  поведение бота не меняется, пока вы сами не переключите). Режим `sdk` держит
  одну живую сессию Claude на проект: контекст не пересобирается заново на каждое
  сообщение, а ответы приходят быстрее.
- **Кнопки прав ✅/❌ в Telegram.** В режиме `sdk` каждое опасное действие
  Claude (запись файла, команда и т.п.) приходит сообщением с кнопками
  «Разрешить / Отклонить» — вы решаете с телефона. Не ответили за
  `permission_timeout_minutes` (по умолчанию 10 мин) — вызов автоматически
  отклоняется. Уточняющие вопросы Claude тоже приходят кнопками с вариантами.
- **Настоящий `/cancel`.** В режиме `sdk` отмена прерывает ход Claude, не убивая
  сессию: контекст сохраняется, следующий вопрос продолжит тот же диалог.
- **Режим `manual`.** Новый четвёртый режим (`/mode manual`): каждое действие
  Claude — только после вашего тапа ✅. Работает только при `runner: sdk`.
- **Очередь сообщений.** В режиме `sdk`, пока Claude думает (или ждёт вашу
  кнопку), новые сообщения не отклоняются, а встают в очередь (до
  `task_queue_max`, по умолчанию 3) и уходят по одному; `/cancel` чистит
  очередь, `/resume` возобновляет её раздачу.
- `/status` и `/config` показывают раннер, очередь и таймаут кнопок; новые
  настройки правятся там же. `stop_bot.bat` заодно прибирает осиротевший CLI
  раннера `sdk` (ваш интерактивный `claude` не трогает).
- Требования: `claude-agent-sdk` в `requirements.txt` (тянет ~200 МБ — CLI в
  комплекте). Без пакета бот работает как раньше на `subprocess`.

## 2026-08-24

- **`/project` — меню с кнопками.** Без аргументов команда теперь показывает
  inline-кнопки по одной на проект (✅ — активный); тап переключает проект,
  меню перерисовывается на месте. `/project <имя>` и `/project add <путь>`
  работают как раньше.
- **Фикс кнопок в старых меню.** Тап по кнопке в удалённом или старше 48 ч
  сообщении теперь присылает свежее меню вместо тихого «ничего не произошло»
  (касается и тогглов `/voice`, `/confirm`, `/draft`, `/reply_voice`, `/note`).
- **Claude больше не путает, где он.** Headless-сессии теперь знают, что
  работают за Telegram-мостом: ответ в чат — только финальный текст. Исчезают
  «план показан выше» и «я не в Telegram» — всё важное приходит в ответе.
